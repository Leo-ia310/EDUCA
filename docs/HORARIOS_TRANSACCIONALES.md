# Horarios: contrato y despliegue

Aplicar 0038 después de 0037 y antes de publicar el backend que llama `schedule_list`/`schedule_write`. Requiere la extensión PostgreSQL `btree_gist`. Preparar backup y ejecutar `backend/scripts/schedules-preflight.sql` sobre una restauración y la base objetivo. Las dos consultas son de solo lectura y deben devolver cero filas. Revisar cualquier conflicto o referencia inválida con la institución; no eliminar horarios automáticamente. La migración valida el histórico y falla si encuentra datos incompatibles.

Las restricciones EXCLUDE comparan institución, año académico y día con intervalos semiabiertos: 08:00–09:00 permite 09:00–10:00. Grupo, maestro y nombre normalizado del aula no pueden solaparse. Recesos generales ocupan todos los grupos de ese año. El turno es una etiqueta, no autoriza solapamientos. El nombre del aula se compara sin mayúsculas ni espacios exteriores, incluso si existen IDs históricos duplicados. Las clases conservan el año de origen; un receso general histórico sin año requiere identificar su año antes de aplicar el cambio si el actual no corresponde.

Las mutaciones administrativas se serializan por institución antes de bloquear filas para evitar deadlocks entre los índices de exclusión. Esto no bloquea consultas ni otras instituciones. La creación de varios días, la resolución/creación del aula y la respuesta se ejecutan en una transacción. El primer conflicto revierte todos los días y cualquier aula creada. Las actualizaciones bloquean y combinan el registro actual en SQL; solo cambian campos enviados. Reasignar maestro/grupo/año o renombrar aulas vuelve a comprobar sus horarios y revierte si genera un cruce. Las escrituras directas también derivan sus campos e índices; no pueden falsear maestro/grupo para evitar la restricción. PostgreSQL puede abortar una operación ante deadlock: conservar el error/reintentar la operación completa, nunca confirmar una escritura parcial.

`GET /api/schedules` acepta `groupId`, `teacherId`, `classId`, `weekdayId`, `shift`, `page` y `pageSize` (50, máximo 100). Devuelve `{ schedules, pageInfo }`, solo del año actual. Los filtros se aplican antes de paginar; un filtro de grupo incluye recesos generales. El frontend ofrece navegación de páginas y selector de grupos con búsqueda, sin depender de la primera página del catálogo.

`GET /api/schedules/mine` conserva `{ schedules }` (incluye metadatos adicionales de paginación que el cliente puede ignorar). Devuelve la semana completa del alcance actual, agregada en SQL sin el límite de filas de PostgREST: matrícula ACT del alumno/hijo autorizado, clases titulares o colaboraciones activas del maestro y recesos correspondientes. Sin clases programadas no muestra recesos aislados. No descarga el horario institucional para filtrarlo en Node.

Permisos administrativos exactos `schedules.view/create/edit/delete`, actor activo, institución y MFA se vuelven a comprobar en SQL. La función interna de DTO no se puede invocar desde clientes. Respuestas: 409 para cruces, 400 datos inválidos, 403 permisos, 404 ID inexistente y 503 fallo de dependencia. No se despliega esta migración automáticamente desde las pruebas locales.

Referencia de la estrategia de exclusión: [PostgreSQL: btree_gist](https://www.postgresql.org/docs/17/btree-gist.html).
